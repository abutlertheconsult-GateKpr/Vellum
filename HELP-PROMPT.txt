WHAT VELLUM IS
Vellum is a PDF app that runs in the browser, installable like an app. It has two sides:
1. Edit a PDF: open a PDF, add text, highlights, shapes, notes, pictures, links, icon buttons, fillable form fields, passwords, undo/redo, templates, and backup/restore.
2. Get signatures: place signature, initials and date boxes, then create a one-time link for each signer. The signer opens the link on any device, signs, and the link stops working. I can download the signed PDF with a signing record page.

HOW IT IS BUILT
- It is a plain static website (no server code of my own), hosted on GitHub Pages (or similar). Files are uploaded by hand. There is no build step.
- Files in the main folder: index.html (the app), sign.html (the page my clients see), check-firebase.html (a connection checker I can open in the browser), sw.js (offline helper), manifest.webmanifest (install info), firestore.rules (database rules), SETUP.md (Firebase setup steps).
- Folders: css/ (styles.css, sigpad.css, signer.css), icons/ (icon-192.png, icon-512.png, logo.png), js/.
- js/ files: state.js, storage.js, history.js (undo/redo), fonts.js, security.js (passwords), nav.js (links and icon buttons), viewer.js, tools.js, forms.js, export.js (builds the saved PDF), textstyle.js, designer.js (form field designer), images.js, pages.js, settings.js (save box, folder, install), sigpad.js (draw/type signature), signprep.js (signature boxes and Send), cloud.js (all Firebase work), home.js, templates.js, backup.js, gestures.js, app.js, signer.js (client page logic), firebase-config.js (MY Firebase settings; the only file meant to be edited by me).
- Libraries loaded from the internet: pdf.js 3.11.174 (cdnjs), pdf-lib "@cantoo/pdf-lib" 2.11.1 (jsDelivr), Firebase 10.14.1 "compat" scripts (gstatic.com): app, auth, firestore.
- The whole app lives in one global object called App. Annotations (marks) are stored per page as fractions of the page (0 to 1), so zooming does not break them.
- sw.js caches files for offline use. To force every device to refresh, change the number in this line near the top of sw.js: const CACHE = 'vellum-v12'; (make it a higher number).
- Local data is kept in the browser's IndexedDB (database name "pdfstudio", store "kv"): the last document, templates (keys tpl:index and tpl:ID), backup link, and the chosen save folder. Passwords are never stored.

HOW SIGNING WORKS (FIREBASE)
- I use a free Firebase project with Email/Password sign-in and Firestore. No paid features, no Cloud Functions, no Firebase Storage.
- firebase-config.js must look exactly like this, with my own values:
  window.VELLUM_FIREBASE = { apiKey: '...', authDomain: '...', projectId: '...', appId: '...', emailExtension: false };
  (It must NOT be replaced by Firebase's own import/const snippet.)
- Firestore collections: requests/{id} (owner only, plus a "chunks" subcollection holding the PDF as base64 pieces), links/{token} (one per signer; token is a long random string; has used, expiresAt, boxes, result, signedAt; plus its own "chunks"), and mail/ (only if the Trigger Email extension is installed).
- Rules are in firestore.rules and must be pasted into Firestore, Rules tab, then Published. Signers need no account: they can read their own link document by its secret name, and can read the PDF pieces only while the link is unused and not expired. They can update the link once to mark it used and save their signature.
- Links expire after 14 days. PDFs up to about 6 MB can be sent. Password-protected PDFs cannot be sent.
- The signed copy is built in my browser from the original file plus each signer's signature image, with a signing record page added at the end.

COMMON PROBLEMS AND WHAT THEY USUALLY MEAN
- "Firebase isn't set up yet" or "can't find your Firebase settings": firebase-config.js still has PASTE_ words, was not uploaded, was replaced with Firebase's own code, or an old copy is cached. Check by opening my-site-address/js/firebase-config.js in the browser.
- "Couldn't load Firebase": an ad blocker, a restricted network, or no internet.
- Sign-in or Create account errors: Email/Password is not enabled (Firebase, Build, Authentication, Sign-in method), or Authentication was never started ("Get started").
- "Missing or insufficient permissions": the Firestore database was not created, or firestore.rules were not pasted and Published.
- The database never answers: not created yet (Build, Firestore Database, Create database), or the network blocks it.
- A signer's link says invalid, expired or already signed: the link was removed, is older than 14 days, or was already used. I can create a new link from Get signatures.
- Old screens after I upload changes: the browser or installed app is showing a saved copy. Fix by raising the number in sw.js, and clearing the site's saved data once (or fully closing and reopening the installed app).
- Something works on a computer but not a phone, or the reverse: ask which device and browser, because folder saving, screen capture and the install button differ by browser.
- Icons or logo missing: the files in the icons folder must be real PNG files with the exact names above.
